# MarginCarry v0.4.0

A highlight or underline can now follow a passage over a page break. After a revision is typeset again, an unchanged paragraph often ends on one page and continues on the next, or a divided paragraph comes back together. MarginCarry transfers such a passage as one native Zotero annotation: from one page to two adjacent pages, from two to one, and from two to two. Longer selections are not supported.

The review dialog shows both pages of the original and of the proposed location, names the page range, and has a button to open each part in the reader. Copying a note relinks these annotations as well.

Matching stays exact. The page break counts as one space of the quote, like a line break, and the passage must be continuous in the PDF's text. If a header, footer, or page number in the text lies between its two parts, or a line-end hyphen sits at the break, MarginCarry says so and transfers nothing. In PDFs whose page numbers are part of the text, this is the usual outcome for a passage across a page break. See [How MarginCarry works](https://github.com/0then0/margincarry/blob/v0.4.0/docs/how-it-works.md#passages-across-a-page-break).

The transfer journal keeps its format, and earlier records, Undo, and repeat protection work as before. The project icon was simplified.

## Installation

Download `margincarry-0.4.0.xpi` below. In Zotero, open **Tools → Plugins**, choose **Install Plugin From File…** from the gear menu, and select the XPI. This release supports Zotero 10.0.5 through 10.0.x. The accompanying `.sha256` file records the package checksum.

## Verification

In an isolated Zotero 10.0.9 profile on macOS, a highlight was created by dragging the mouse across a page break in the reader. The dialog showed both pages on each side; the transferred highlight kept its text, comment, color, and tags and had the independently computed rectangles on both pages. It was still there after reopening the PDF, a copied note linked to it, and Undo removed only that copy. One page to two and two pages to one were checked the same way, and a PDF with page numbers was refused with its reason.

These checks ran on builds of the same code made before the version number changed, not on the published package. Following a copied link by clicking it in the note editor, a restart between apply and Undo, PDFs in which the reader marks headers or footers as isolated, and the real revision corpus were not checked. Details are in [Validation](https://github.com/0then0/margincarry/blob/v0.4.0/docs/validation.md).
